# Writeup #1 — Corpus construction & normalisation

*Hand-authored (M2-T6), 2026-08-13. Unlike the generated reports in this directory,
this one is written and maintained by hand; the numbers in it are regenerated by the
scripts cited inline. Data © StatsBomb — used under the StatsBomb Public Data User
Agreement; SPADL follows Decroos et al., KDD 2019 (socceraction 1.5.3).*

## 1. What the corpus is

One provider: **StatsBomb Open Data**, pinned at commit `b0bc9f22` (manifest.yaml).
Everything StatsBomb has released enters, except the Indian Super League:
**3,846 matches, 13.57M events, 9,607 players, ~368k minutes** across 79
competition-seasons (`reports/00_coverage.md`, regenerated from disk on every run —
no count in this project is ever hardcoded).

Two properties of the corpus are inherited from what StatsBomb chose to release,
not chosen by us:

- **All-teams league seasons exist only for 2015/16** (La Liga, Premier League,
  Serie A, Ligue 1; ~1,517 matches) plus the modern women's leagues. There is no
  all-teams Bundesliga season at all.
- **Everything else is a slice**: Messi's Barcelona/PSG/Miami matches, Arsenal
  03/04, Leverkusen 23/24, star-selected matches of old World Cups. Slices are
  accepted knowingly — they are the only form that data exists in, and they enable
  the longitudinal (Messi) and era-control (Arsenal) studies. Their opponents
  appear in 1–2 matches each, which is exactly the sparse-entity case the
  shrinkage machinery (PLAN Part 5) exists for.

Wyscout remains on disk, pinned and hashed, but nothing is ingested from it —
the provider-precedence and carry-inference-benchmark work is dormant, not deleted.

## 2. The unit of analysis

The represented entity is **(player_id, season, context)** — never the pooled
career (styles drift; De Bruyne 17/18 vs Özil 15/16 is a meaningful comparison,
"De Bruyne the career" is not a style). Within one season, all **club**
competitions pool into one entity and all **national-team** competitions into a
separate one, split by StatsBomb's `competition_international` flag (Champions
League correctly lands club-side). Penalty shootouts (period 5) are excluded from
every aggregate. Current roster: **17,666 entities** (`player_season_context`
view in `data/football.duckdb`).

## 3. The three layers

```
raw      pinned clone, provider format, source of record (14 GB JSON)
staging  same facts re-housed: flat typed Parquet, one file per comp-season,
         events + lineups + matches, 14x compression (0.83 GB), zero semantic change
spadl    the normalised action table: 7.78M on-ball actions, 105x68 m,
         23-type vocabulary, acting team always attacks left -> right
```

Staging is deliberately a **format change only** — no coordinate conversion, no
vocabulary mapping (decision D7). All semantic normalisation happens once, in the
SPADL stage, via socceraction's maintained converters (D12): a non-bijective
mapping (pressures, receipts and other off-ball events are dropped — they remain
queryable in staging), so the layer mints its own primary key **(game_id,
action_id)** and carries `original_event_id` as lineage back to raw.

Relationally, the SPADL layer is a star schema: BCNF dimension tables
(actiontypes / results / bodyparts) around a fact table that deliberately folds
the match keys back in (competition_id, season_id, provider) — one step below
3NF, safe because every table is immutable and rebuilt whole by `dvc repro`.
The full F / canonical-cover / synthesis derivation lives in the project notes.

One vocabulary trap worth repeating in every downstream discussion: StatsBomb
**Carry** → SPADL **dribble**; StatsBomb **Dribble** (the take-on) → SPADL
**take_on**. SPADL "dribble" means moving with the ball, not beating a man.

## 4. Evidence the gates work

The validation layer (M1-T8/T10) was allowed to fail loudly, and its first runs
caught real upstream quirks — each investigated, bounded, and exempted precisely
rather than papered over (`reports/03_failures.md`):

1. Sub-yard coordinate overshoots at pitch edges (~700 of 13.57M rows, max
   120.9/80.9) — the provider's real envelope is ±1 yard.
2. Half-boundary timestamp regressions (582 rows): stoppage-time passes whose
   receipts are stamped on the next period's reset clock (also in extra-time
   periods), plus sub-3-second whistle jitter. `index` is canonical order;
   duration features must never difference raw timestamps across boundaries.
3. A full SPADL rebuild reproduced the layer to within one unexplained row in
   7.8M (all structural checks identical) — recorded and watched.

The orientation assertion (mirrored-coordinate tripwire) passes on every
comp-season: lowest median shot x is 94.1 on a 0–120 axis where a mirrored
corpus would sit near 20. Reconciliations hold end-to-end: staging row count
equals the coverage report's event count exactly; SPADL's 3,846 games equal the
corpus match count exactly.

## 5. Identity and labels

StatsBomb ids resolve to Transfermarkt through reep's bridges (ids only, no name
matching): **73.2% of men's players, 0.0% of women's** — reep's StatsBomb bridge
and the Transfermarkt dataset are both effectively men's-football-only
(`reports/identity_resolution.md`). Consequences:

- Transfermarkt-derived labels (bios, transfer pairs for E5, appearance counts)
  are **men-only**. Hand-patches go in `src/harmonise/identity_overrides.csv`.
- **Market value is dropped from the project entirely** (D13) — confounded by
  country/league economics, and it would have covered only men anyway. The
  quality axis is event-derived (VAEP / xG+xA per 90), which every entity has.
- Women's data (≈29% of the corpus) fully serves style training and the
  men→women transfer study (E8).

## 6. Reproducibility contract

`manifest.yaml` pins what the world gave us (commit SHAs, DOI versions, file
hashes); DVC tracks what we produce (staging, SPADL, identity map, the DuckDB
view file) with `dvc.lock` binding each git commit to exact data hashes; and
`config.yaml` is the single place the corpus is defined. `dvc repro` rebuilds
and re-validates everything that changed, and nothing downstream ever reads raw
JSON except the SPADL stage's maintained loader.
